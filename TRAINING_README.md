# Nexus 3B Lab: Training & Fine-Tuning Guide

This document explains the technical concepts behind the "Process Book" capability for improving the local model.

## 1. The Dataset: `training_data.jsonl`

To improve the model, we need examples of **Good Interactions**. We store these in a JSONL (JSON Lines) file.
**Structure:**
Each line is a valid JSON object representing one training example.

```jsonl
{"prompt": "User: What is photosynthesis?\nSystem:", "response": "Photosynthesis is the process used by plants to convert light energy into chemical energy.", "score": 9}
{"prompt": "User: Write a python function to add two numbers.\nSystem:", "response": "def add(a, b):\n    return a + b", "score": 10}
```

-   **prompt**: The input given to the model (including system/user prefixes).
-   **response**: The *ideal* or *good* output generated by the model.
-   **score**: A human rating (1-10) indicating how good this example is.

---

## 2. Data Curation: "Score > 7"

**What does filtering mean?**
Not all model outputs are good teaching examples. If the model hallucinates or gives a wrong answer, we *do not* want to train on it.
**Filtering Score > 7** means we only feed the trainer examples that you (the human expert) have rated 8, 9, or 10.
-   **Low Quality Data** = Degrades the model (Model collapse).
-   **High Quality Data** = Improves the model (Alignment).

---

## 3. LoRA (Low-Rank Adaptation)

**The Problem:**
Fine-tuning a 3 Billion parameter model usually requires updating all 3B weights, which takes massive amounts of memory (VRAM) and storage.

**The Solution (LoRA):**
LoRA freezes the 3,000,000,000 original weights. It injects tiny, separate "Adapter" matrices (e.g., only 10,000,000 params) into the model.
-   **Training**: We only update these tiny matrices.
-   **Result**: Training is 10x faster and requires 1/3rd the VRAM.

---

## 4. Adapters

**What are they?**
An "Adapter" is the small file (approx. 10-100MB) generated by LoRA training. It contains *only* the new knowledge or style you taught the model.
-   **Base Model**: The original brain (Generic knowledge).
-   **Adapter**: The specialized skill (e.g., "Coding style", "Your personal tone").

**At Inference Time:**
We load `Base Model + Adapter`. The model now behaves as if it was fully re-trained.

---

## 5. Fine-Tuning Process

**Fine-Tuning** is the act of taking a pre-trained model (like StableLM-Zephyr) and training it further on your specific dataset.

**Our Loop:**
1.  **Chat**: You generate text.
2.  **Rate**: You identify good responses.
3.  **Train**: `train.py` reads the JSONL, calculates the error, and updates the weights.
    ```bash
    # Basic usage (defaults to stabilityai/stablelm-zephyr-3b)
    python train.py

    # Advanced usage (specify your own model)
    python train.py --model_id "your-org/your-custom-model" --output "my_adapters"
    ```
4.  **Save**: The new Adapter is saved to disk.
